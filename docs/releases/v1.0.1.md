# Release v1.0.1

[![GitHub Downloads](https://img.shields.io/github/downloads/alexdelprete/ha-droplet-plus/v1.0.1/total?style=for-the-badge)](https://github.com/alexdelprete/ha-droplet-plus/releases/tag/v1.0.1)

**Release Date:** 2026-08-17

**Type:** Patch release - Fix inflated water consumption totals.

## What's Changed

### Fixed

- **Consumption totals no longer double on integration reload.** The
  pydroplet library keeps volume accumulators in state shared by every
  Droplet connection in the process, so a reload (e.g. after changing the
  water tariff or leak threshold) silently kept the previous accumulator's
  volume and double-counted every period total. Droplet Plus now removes
  stale accumulators before registering fresh ones at setup, and
  deregisters them on shutdown. Reported in #12 — thanks to Peter
  ([@guytpetj](https://github.com/guytpetj)) for the detailed testing that
  confirmed the diagnosis!

### Known Issues

- **Do not run the core Droplet integration alongside Droplet Plus.** Due
  to the same shared-state bug in the pydroplet library (reported upstream:
  [Hydrific/pydroplet#7](https://github.com/Hydrific/pydroplet/issues/7)),
  each additional connection to the device feeds Droplet Plus's consumption
  counters, doubling the totals. Until a fixed pydroplet release ships, run
  only one of the two integrations.
- Consumption history recorded while affected by the bug remains inflated in
  Home Assistant's long-term statistics. It can be adjusted or deleted via
  **Developer Tools → Statistics**.
